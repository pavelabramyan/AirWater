# МЕТА-ПРОМПТ: составить исполнительный промпт на редизайн лендинга AquaFuture

## Твоя роль и задача
Ты — senior prompt engineer с экспертизой арт-директора и ведущего фронтенд-разработчика.
Твоя задача — НЕ выполнять редизайн, а написать один исполнительный промпт (ТЗ) для

## Задача, которую будет решать исполнитель
Редизайн одностраничного инвестиционного лендинга AquaFuture: сделать дизайн
максимально красивым, живым и анимированным, строго mobile-first, не сломав
ни одну существующую функцию.

## Контекст проекта (перенеси в итоговый промпт без потерь)
- Продукт: лендинг для инвесторов в производство премиальной питьевой воды из
  воздуха (AWG). Чек: $150k–$960k. Тон: премиум, технологии, доверие; вода —
  главная метафора бренда.
- Стек: статика без сборки — index.html (~650 строк), styles.css (~1330 строк),
  vanilla JS: main.js (UI/анимации/форма), calculator.js (бизнес-логика ROI —
  не трогать), wizard.js (мобильный 3-шаговый мастер), comparison.js, chart.js
  (Chart.js 4.4), map.js (Leaflet 1.9.4), i18n.js (RU/EN/ZH/ES через data-i18n).
  Хостинг GitHub Pages; сайт должен работать и при открытии через file://.
- Секции: фикс-навбар; hero со счётчиками и динамической строкой расчёта;
  about (4 карточки); калькулятор (3 сценария, wizard на мобиле, 8 карточек
  результатов, карта Leaflet, график Chart.js); сравнение 4 локаций; флагманская
  секция «Бали»; trust (6 карточек); advantages (4 пункта); структура инвестиций;
  roadmap-таймлайн 7 этапов; форма заявки; футер.

## Аудит текущего дизайна (итоговый промпт обязан закрыть каждый пункт)
A. Айдентика: генерик-шаблон — плоские белые карточки, дефолтный синий #0066cc,
   эмодзи вместо иконок, шаблонные тени; метафора «вода из воздуха» не обыграна.
B. Консистентность: Бали (teal→orange), контакты (плоский синий градиент) и
   roadmap (Apple-серый) — три разных визуальных языка; 3+ стиля карточек.
C. Токены: в :root только 6 цветов и 3 тени; нет шкал отступов, радиусов,
   типографики; акцидентный шрифт Syne используется только в hero.
D. Мобильная навигация отсутствует: ниже 968px .nav-links скрыт, бургера нет.
E. Якорные переходы обрезают заголовки под фикс-шапкой (нет scroll-margin-top).
F. CSS desktop-first (только max-width); hero на min-height:100vh (iOS-баг,
   нужен svh/dvh).
G. Анимаций мало: fadeInUp в hero, 2 блоба, fade-in карточек (инлайн-стили из JS),
   каунт-ап только в hero. Нет скролл-хореографии, каунт-апа результатов
   калькулятора, микровзаимодействий, живого фона; шаги wizard — display:none.
H. Семантика данных: отрицательный NPV чёрным; нет success/danger-кодирования.
I. A11y: нет prefers-reduced-motion; touch-таргеты < 44px (кнопки «?» — 18px);
   фокус-стили частичны.

## Целевое направление (зафиксируй как арт-дирекшн)
«Живая вода + премиальные технологии»: глубокие сине-циановые градиенты,
дозированный glassmorphism, волновые SVG-разделители секций, капли и влажность
как визуальный мотив, постоянное но ненавязчивое движение: фон дышит, числа
оживают каунт-апом, карточки отвечают на касание. Ощущение дорогого
финтех-продукта. Бали остаётся тёплым акцентом, но внутри единой системы.

## Жёсткие ограничения (в итоговый промпт дословно)
1. Стек не менять: без фреймворков, сборщиков и тяжёлых библиотек. Анимации —
   CSS + Web Animations API + IntersectionObserver + requestAnimationFrame.
   Разрешён свой canvas-модуль для фоновых частиц (< 5KB кода).
2. Не ломать функциональность: сохранить все DOM id, классы-хуки JS и атрибуты
   data-i18n / data-i18n-placeholder; тексты и переводы не менять; бизнес-логику
   calculator.js / locations.js не трогать.
3. Вёрстка обязана выдерживать все 4 языка (ZH короче, ES/RU длиннее).
4. Mobile-first: базовые стили — мобильные; media queries только min-width;
   брейкпоинты 640 / 968 / 1200 или обоснованные свои.
5. prefers-reduced-motion: reduce — декоративные анимации отключаются,
   функциональные упрощаются до fade.
6. Perf-бюджет: 60fps (анимировать только transform/opacity, will-change
   точечно), LCP < 2.5s на мобиле, CLS < 0.1, без новых блокирующих ресурсов.
7. Правки в styles.css и index.html (разметка — только обёртки/бургер/декор);
   в JS — только UI-слой (main.js, wizard.js) и новые модули вроде animations.js.

## Структура, которую обязан иметь итоговый промпт
1. Роль исполнителя и цель одним абзацем.
2. Контекст проекта целиком (из этого документа).
3. Дизайн-система в конкретике: палитра с HEX (основа, поверхности, семантика
   success/danger), типографская шкала (Syne — все заголовки, Inter — текст,
   конкретные clamp()-значения), шкала отступов, радиусы, тени, glass-эффекты —
   всё именованными CSS custom properties.
4. Посекционный план: для каждой из 13 секций — что меняется визуально,
   раскладка на 390px и 1280px, какой декор добавить.
5. Спецификация анимаций списком: элемент → триггер (load / вьюпорт / hover /
   изменение значения / скролл) → эффект → длительность и easing → stagger →
   поведение на мобиле и при reduced-motion. Минимум покрыть: вход hero, живой
   фон, каунт-ап ВСЕХ чисел (включая результаты калькулятора при пересчёте),
   stagger-появление карточек, рисование линии roadmap по скроллу,
   слайд-переходы шагов wizard, микровзаимодействия кнопок (press) и инпутов
   (focus glow), волновые разделители, липкий мобильный CTA.
6. Мобильная навигация: бургер 44×44, выезжающая панель с анимацией,
   aria-expanded, блокировка скролла, закрытие по тапу на ссылку.
7. Обязательные UX-фиксы: scroll-margin-top под высоту шапки; 100vh → 100svh;
   touch-таргеты ≥ 44px; отрицательные NPV/ROI — danger-цветом.
8. A11y: контраст ≥ 4.5:1, :focus-visible, aria для бургера/wizard/тултипов.
9. Протокол проверки через chrome-devtools MCP: скриншоты 390/768/1280 до и
   после (hero, калькулятор с выбранной страной, сравнение, Бали, roadmap,
   форма); прогон wizard на 390px; переключение всех 4 языков; console без
   ошибок; эмуляция prefers-reduced-motion.
10. Definition of Done чек-листом.
11. Порядок работы: токены → глобальные фиксы → навигация → hero → секции по
    порядку → анимации → проверка; коммит и push после каждого логического
    блока (правило проекта).
